Rollout Plan — Ride Scheduler on Microsoft Lists (Branch A)

Park Avenue Community Center · Senior Nutrition + Transportation · getting it live
Privacy guardrail (applies to every phase): rider names, addresses, and phone numbers stay inside Microsoft 365. The only AI allowed on rider data is Microsoft Copilot (work scope). Never paste rider PII into any outside AI.

This is the step-by-step plan to take the artifacts already built in branch-a-lists/ and turn them into a working weekly system at the center. Each phase has an owner, a rough time, and a "done when" check. Do the phases in order; Phase 0 is already complete.

Phase 0 — Build the artifacts Done

Owner: completed · committed & pushed to claude/ai-workflow-work-rf1gg2
Schema, import workbook, 4 views, per-driver email flow, email/Teams templates, Copilot prompts, and the setup guide are all written, with your 3 decisions folded in (Yes/No FACT flag, 4 roles, per-driver Outlook email). See CHANGES.html.

Phase 1 — Confirm access & gather real details Start here

Owner: you · ~30 min · no rider data leaves M365
  • Open office.com → app launcher (9 dots) → confirm Lists and Power Automate both open with your work account.
  • Collect the 4 real email addresses for the role map: Driver 1, Driver 2, FACT Coordinator, Supervisor.
  • Confirm the real role labels (keep "Driver 1/2" or rename to people's names — your call).
  • Decide where the list lives: a SharePoint/Teams site the team shares (recommended) vs. personal. The flow needs the site address.
  • Have this week's paper schedules handy for the Phase 5 pilot.
Done when: you can open Lists + Power Automate, and you have the 4 emails written down.

Phase 2 — Create the List Next

Owner: you · ~30 min · follow LIST-SCHEMA.md
  1. Lists → New list → From Excel → upload Schedule for Lists Import.xlsx.
  2. In the preview, fix column types: Assigned Driver → Choice (4 roles), Outside Ride (FACT/Lyft) → Yes/No, time columns → Date and time.
  3. Name it Senior Rides Schedule → Create.
  4. Apply the 3 color JSONs from column-formatting/ (Zone, Outside Ride, Trip Type).
  5. Rename the built-in Title column → Rider.
Done when: the list shows 10 sample rows with colored pills and the right column types.

Phase 3 — Build the 4 views Next

Owner: you · ~20 min · follow views.md
  • Calendar — the week at a glance (driven by Pickup Time).
  • By Driver — grouped by role, filtered to Outside Ride = No (van runs).
  • By Day — grouped by Day, sorted Zone → Time (routing starting order).
  • FACT / Lyft riders — filtered to Outside Ride = Yes (the coordinator's list).
Done when: all 4 view tabs appear and show the expected rows.

Phase 4 — Build & test the email flow Next

Owner: you · ~45 min · follow power-automate-flow.md
  1. Power Automate → new Scheduled (Recurrence) flow.
  2. Initialize the roleEmails object with the 4 real addresses from Phase 1.
  3. Get items → build the 4 branches: Driver 1, Driver 2 (their van runs), FACT Coordinator (Yes list), Supervisor (all).
  4. Drop in the bodies from email-template.md.
  5. Test → Run once. Confirm 4 emails arrive, each with the right slice.
Done when: a test run sends all 4 emails correctly and the run history is green.

Phase 5 — Pilot one real week (parallel to paper) Next

Owner: you + coworker · 1 week · keep the old process running as backup
  • Delete the 10 sample rows; enter this week's real rides with the + New form.
  • Run the flow (or wait for the schedule). Have the 2 drivers + coordinator + supervisor confirm their emails look right.
  • Make one mid-week change and confirm the update reaches the right person.
  • Note anything awkward — wrong columns, missing field, sort order — and adjust.
Done when: the team agrees the emails match what they'd have gotten on paper, with no surprises.

Phase 6 — Go live + train coworker Then

Owner: you + team · ~1 hr
  • Stop the paper compile; the List is now the source of truth.
  • Share the List with the team (read or edit as appropriate).
  • Walk your coworker through the weekly routine in SETUP-GUIDE.md (form entry → check views → flow sends).
  • Bookmark the Copilot prompts in copilot-prompts.md for notices/summaries.
Done when: either you or your coworker can run a full week solo.

Phase 7 — Later: reporting + route optimization Future

Owner: TBD · separate branches, not blocking go-live
  • Monthly totals for County/grant reporting (meals + rides served) — a simple grouped/summed view or a small flow.
  • Intake form so staff/family submit ride requests straight into the List — cuts paper transcription.
  • Route optimization (the known gap): true best pickup order / van assignment by distance. M365 can't do this cleanly; it needs a mapping/routing service (e.g. Azure Maps) vetted for the data boundary. Today the By-Day Zone→Time order is the hand-finishable starting point.
Decision needed before starting: which of these three is worth the effort first — tell me and I'll spec it as its own branch.
